# 網站維護說明

這個網站是 GitHub Pages 靜態站（`main` 分支根目錄），用 Tailwind CDN。`blog/` 是用腳本產生的，**不要直接手改 `blog/` 裡的檔案**。

## 網站結構
| 頁面 | 檔案 | 說明 |
|---|---|---|
| 首頁 | `index.html` | 手寫。品牌區、研究與服務方向（4 張卡片）、成員（JP）、專業服務（目前是預留空位）。不放部落格內容，其他頁面從導覽列進入 |
| 成員專長（履歷） | `resume.html` | 手寫。身份背景、職責貢獻、專業技能、核心優勢 |
| 成員作品（作品集） | `portfolio/index.html`、`portfolio/{網址代稱}.html` | 外框手寫；`<!-- WORKS:START -->` 到 `<!-- WORKS:END -->` 之間的卡片與每個作品的案例頁由腳本從 Notion「作品」資料庫產生，**不要手改**，見下面「成員作品」一節 |
| 專業服務 | `index.html` 的 `#services` 區塊 | 目前只有「服務項目準備中」的預留空位，之後在這裡放服務項目卡片 |
| 成員個人空間（部落格） | `blog/` | 腳本產生。第一頁「JP 的個人空間」＝「現在在做的事」大區塊＋便條紙牆（每張便條紙是一個專區）；`blog/zone/*.html` 是各專區內頁；`blog/all.html` 是全部文章（搜尋、分類篩選）；`blog/posts/*.html` 是文章 |

成員專長、成員作品兩頁的大標用成員代稱（現在是「JP 的專長」「JP 的作品」），不要跟導覽列文字重複；之後每位成員各有一組頁面時，也照這個命名。

導覽列在 `index.html`、`resume.html`、`portfolio/index.html` 各自手寫一份，部落格頁面與作品案例頁的導覽列寫在 `tools/build_blog.py` 的 `HEAD`（案例頁會自動把高亮換成「成員作品」）。新增或改名頁面時，這四處要一起改。

品牌名是「JPK Lab」（遊戲化思維實驗室）。成員只用代稱（目前只有 JP），不放本名。首頁受眾是合作與服務對象，部落格則是純興趣、研究與生活分享。新增成員時，複製首頁 `#members` 裡的 `<article>` 卡片即可。

## 個人空間的版面設定（`tools/blog_config.json`）
- `now`：「現在在做的事」區塊。`paragraphs` 第一段是大字，之後的段落是內文；`updated` 是顯示的更新日期（改內容時一起改）。
- `groups`：便條紙牆的分組與順序（目前是「工作與創作」「興趣與生活」）。
- `zones`：便條紙牆。每個專區有 `slug`（網址用）、`name`、`group`（屬於哪一組，要寫在 `groups` 裡）、`categories`（哪些文章分類屬於這個專區）、`color`（便條紙底色）、`summary`（便條紙上的摘要）。組內的順序就是 `zones` 裡的先後。沒有文章的專區會顯示成不能點的便條紙「尚無文章」，有文章後自動變成可點，並產生內頁。
- 文章分類不在任何專區時，建置會印出 WARNING，文章仍會出現在 `all.html`，但便條紙牆看不到，要補一個專區。
- 目前專區（12 張便條紙）：工作與創作＝AI創作、專業學習、外語學習、虛擬歌手創作、遊戲試玩、碎碎唸；興趣與生活＝運動健身、營養學、當個農夫、探索世界、生活記事、Vtuber廢片。2026-10-12 已移除「舊文存檔」專區與其 44 篇（分類「未分類」）舊文，公開網站不再放早期舊文，內容只留在 Notion。便條紙摘要取自 Notion 各區頁面的標語。Notion 的區頁面名稱多一個「區」字（例如「AI創作區」），對應的分類選項沒有。

## 從 Notion 同步新文章
Notion 資料庫「部落格文章」（在「我的簡介」頁面下）是寫作的地方，網站是從它產生的。作業流程：
1. 本人在 Notion 寫文章，填好 `分類`（要是上面專區對應的分類之一）、`發布日期`，把 `狀態` 設成「待發布」，`來源` 選 Notion。**狀態設成「待發布」就代表同意公開。**
2. 同步（二選一）：
   - **按鈕**：到 GitHub 儲存庫 → Actions → 「同步 Notion 文章」→ Run workflow（見下一節，圖片會自動處理）。
   - 告訴 Claude「同步 Notion」，由 Claude 在對話裡處理（圖片不會自動搬，要用下面「在文章裡放圖片」的手動做法）。
3. 同步後，本人把 Notion 的 `狀態` 改成「已發布」（只是給自己看的標記，網站不看它；整合是唯讀，不會自動回填）。
- 規則：只有狀態＝「待發布」的頁面會被**新增**。Notion 裡狀態是「已發布」的舊文、私人文章、草稿，一律不會被加進網站。
- 改已發布的文章：在 Notion 直接改。按按鈕時，網站上有對應 `notion` 欄位、狀態是「待發布」或「已發布」的文章，只要 Notion 的最後編輯時間比 `posts.json` 記的（`notion_edited`）新，就會自動更新。要「下架」請本人說，由 Claude 從 `posts.json` 移除（只把 Notion 狀態改回寫作中不會下架）。
- 新增分類：Notion 的 `分類` 選項、`blog_config.json` 的 `zones` 與 `category_order` 三處要一起加。
- 舊的 `初音V家`、`虛擬創作` 分類已合併成「虛擬歌手創作」，Notion 裡這兩個選項沒有文章了。

## 成員作品（從 Notion 同步）
Notion「作品」資料庫（在「我的簡介」頁面下）是維護作品的地方。每個作品＝一頁：**欄位放卡片摘要，頁面內文寫短案例**，詳細的開發過程留在部落格，用「相關文章」連過去。

| 欄位 | 說明 |
|---|---|
| 作品名稱 | 卡片與案例頁的標題 |
| 一句話說明 | 卡片簡介，一到兩句（必填） |
| 專案進度 | 概念驗證／開發中／測試中／已上線／已結案。照實標示 |
| 技術與工具 | 標籤 |
| 網址代稱 | 案例頁網址用，只能英文小寫、數字、連字號，例如 `life-opera`（必填，不能是 `index`、`img`） |
| 顯示順序 | 數字小的排前面 |
| 成品連結、GitHub 連結 | 選填，只接受 `https://`，會顯示在卡片與案例頁 |
| 相關文章 | 連到「部落格文章」資料庫的開發過程文章；案例頁底部會列出，**只列出已經在網站上的文章** |
| 網站顯示 | 草稿＝不上網；**待發布或已發布＝同意公開** |

流程：
1. 在 Notion 寫好作品頁，確認內容沒有金鑰、帳號、真實使用者資料、前雇主內部資訊後，把 `網站顯示` 改成「待發布」。
2. 同步：Actions →「同步 Notion 文章」→ Run workflow（文章與作品一起同步）。
3. 之後改內容：在 Notion 直接改，再按一次同步。**下架**：把 `網站顯示` 改回「草稿」再同步，案例頁與它的圖片會一併清掉（作品是整批以 Notion 為準，不需要請 Claude 手動移除）。
- 作品頁的圖片：Notion 頁面裡放的圖片區塊會自動下載、縮圖、移除 EXIF，存成 `portfolio/img/w-{網址代稱}-{8碼}.jpg/png`；內文裡單獨一行 `[圖:檔名|圖說]` 也有效，找不到時會從 `blog/img/` 複製一份。手動放進 `portfolio/img/` 的圖不會被動到。
- 保護機制：作品資料庫讀不到（例如還沒把整合加進這個資料庫）時，網站上的作品維持原樣，並讓這次同步顯示失敗；查到 0 筆但網站已有作品時也不會整批清空；單一作品名稱、說明或代稱不合格時，只略過那一個，並寫在 Summary 的「作品需要處理」。
- 重建作品頁：`python3 tools/build_works.py`（需要 `pip install markdown-it-py`）。資料在 `tools/works.json`（由同步產生，不要手改）。
- 作品卡片的第一張圖會當縮圖；沒有圖就顯示預設圖示。

## 自動同步（GitHub Actions）
檔案：`.github/workflows/sync-notion.yml`（流程）、`tools/sync_notion.py`（腳本）、`tools/test_sync_notion.py`（離線測試，不連網，涵蓋文章與作品）。

**一次性設定（本人要做）**
1. 到 https://www.notion.so/profile/integrations 建立「內部整合」，權限只勾「讀取內容」（唯讀），複製金鑰。
2. 打開 Notion「部落格文章」資料庫，右上角 ⋯ → 連線（Connections）→ 加入剛建立的整合。沒分享給它的頁面它看不到。**「作品」資料庫也要做同樣的連線**（它是獨立的資料庫，不會跟著繼承）。
3. GitHub 儲存庫 → Settings → Secrets and variables → Actions → New repository secret，名稱填 `NOTION_TOKEN`，內容貼上金鑰。**金鑰只放這裡，不要貼到對話、檔案或儲存庫。**

**每次使用**
- Actions 分頁 → 「同步 Notion 文章」→ Run workflow。結果在該次執行的 Summary（新增幾篇、更新幾篇、需要處理的項目）。
- `resync` 欄：強制重新同步指定文章，填 id（例如 `688,705,706`）或 `all`；一般留空。
- `dry_run` 勾選＝試跑，只檢查，不提交、不更新網站。第一次建議先試跑。
- 之後想要每天自動同步，把工作流程檔裡 `schedule` 兩行的 `#` 拿掉即可。（公開儲存庫連續 60 天沒有任何活動時，GitHub 會自動停用定時執行，手動按鈕不受影響。）

**圖片怎麼處理**
- Notion 的圖片網址約 1 小時就過期，所以腳本每次執行時才向 Notion 取得最新網址，馬上下載。
- 圖片會縮到 1600 px 寬以內、壓到約 1 MB、**移除 EXIF（含手機拍照的 GPS 位置）**，存成 `blog/img/p{文章id}-{8碼}.jpg/png`（動態 gif 保留原檔）。同一張圖不會重複下載。文章裡自動寫入 `[圖:檔名|圖說]`，Notion 圖片的「說明」會變成圖說。
- 文章在 Notion 改掉或刪掉圖片後，再同步會自動清掉不用的 `p{id}-*` 圖檔；手動上傳到 `blog/img/` 的圖片不會被動到。
- 腳本在 Notion 手動寫單獨一行的 `[圖:檔名]` 仍然有效。
- 儲存庫是公開的：圖片上網後任何人都看得到。**只有狀態為「待發布」（或已同步過的）文章的圖片會被下載。**

**安全設計**
- 整合唯讀，腳本不會改 Notion。日誌只印文章標題與圖片檔名，不印內文、金鑰或圖片網址（Notion 圖片網址帶簽名，而日誌任何人都看得到）。
- 沒填發布日期、分類不在任何專區的頁面會被略過並列在 Summary 的「需要處理」。子頁面（child_page）不會被輸出。
- 第一次執行時，已有 `notion` 欄位但還沒有 `notion_edited` 的既有文章只會記下編輯時間基準，內容不動；要補圖請用 `resync` 指定。

**已知限制**
- 程式碼區塊、表格會轉成逐行文字；Notion 的 PDF／音訊／上傳影片檔無法搬運（會在 Summary 提醒）；刪除線、顏色、底線格式不保留。
- 沒有在真實 Notion 與 GitHub 上跑過的部分（API 欄位、圖片主機連線、Pages 自動重建）要靠第一次執行驗證，離線測試只涵蓋轉換與圖片處理邏輯。

## 在文章裡放圖片
1. 把圖片（建議寬度不超過 1600 px、檔案 1 MB 以內，檔名只用英文字母、數字、`-`、`_`，副檔名 png/jpg/jpeg/gif/webp）放進 `blog/img/`。用 GitHub 網頁操作：儲存庫 → `blog/img` 資料夾 → Add file → Upload files → 把圖拖進去 → Commit changes。
2. 在文章內文（Notion 或 `posts.json`）想放圖的位置，單獨一行寫 `[圖:檔名.png]`，要加圖說就寫 `[圖:檔名.png|圖說文字]`。
3. 重新建置。找不到圖檔時，建置會印 WARNING（那一行不會顯示圖片）。
- 文章的 `media` 欄位是「原文有幾張圖片或影片」，已放上圖的張數會自動從「尚未移轉」的提示裡扣掉。
- 儲存庫是公開的：圖片上網後任何人都看得到，不要放含個人資料（真實聯絡人、帳號、金鑰）或有版權疑慮的圖。
- 這是**手動**做法（讓 Claude 在對話裡同步時用）。用 GitHub 按鈕同步時，圖片會自動處理，見上一節。Claude 的工作環境連不到 Notion 的檔案伺服器，所以那邊只能手動放。

## 重新產生部落格
```
pip install markdown-it-py
python3 tools/build_blog.py
```
- 文章資料：`tools/posts.json`（欄位：id、date、category、title、md、media）
- 設定：`tools/blog_config.json`
  - `hidden_ids`：不顯示的文章 id（網站上會消失，但 posts.json 裡仍有資料）。**儲存庫是公開的，不想讓人看到的文章不要放進 posts.json**，私人文章只留在 Notion（狀態不要設「待發布」）
  - `category_labels`：分類顯示名稱（目前沒有設定任何改名）
  - `category_order`：分類排序
- 腳本會重建 `blog/` 底下的 `index.html`、`all.html`、`zone/*.html`、`posts/*.html`，不會動首頁和其他頁面。作品頁另外用 `python3 tools/build_works.py` 重建（GitHub 按鈕同步時兩個都會跑）。

## 新增一篇文章
在 `tools/posts.json` 加一筆：`id`（不可重複的整數）、`date`（YYYY-MM-DD）、`category`、`title`、`md`（內文，一行一段，空行用 `<empty-block/>`）、`media`（略過的圖片數，沒有填 0）。再執行上面的建置指令。
